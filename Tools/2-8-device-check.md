# 2-8 실기기 검증 절차 (iPhone 12 · Xcode 콘솔)

세션 방향 확정(2-8)의 실기기 게이트다. 하네스(`Tools/StorageCheck.swift`)는
카메라 없이 도는 것만 본다 — 촬영·탭이 필요한 네 항목이 여기 있다.

**빌드 전제**: `be4b794`(도출 방향 로그) 이상. 그 이전 빌드로 돌리면 항목 4의
핵심 줄이 아예 찍히지 않는다.

## 콘솔로 판정 가능한가

| 항목 | 판정 | 근거 로그 |
|---|---|---|
| 1. 첫 클립 → `.decided` | 가능 | `[probe] 도출 방향=` + `[probe] 방향=` |
| 2. 재실행 후 `.resumed` | 가능 | `[probe] ▶ 이어가기` vs `[probe] + 새 세션` |
| 3. `.missing` 세션 불변 | **픽스처가 있을 때만** | 실행마다 자동으로 도는 `inventory` |
| 4. 거꾸로 촬영해도 `.portrait` | 가능 | `[probe] 도출 방향=` 두 줄 |

**항목 4는 두 줄을 함께 봐야 한다.** `방향=`만 보면 도출이 틀려도 통과한다 —
두 번째 이후 클립은 `decideOrientation` 가드에 막혀 세션 방향을 어차피 바꾸지
않기 때문이다. 가드가 막아준 것과 도출이 맞은 것을 가르는 것이 `도출 방향=`
줄이다.

## 0. 준비 — 현재 상태를 먼저 기록한다

**기기 상태를 절차에 박지 않는다.** 세션이 몇 개이고 어떤 상태인지는 실행할
때마다 다르다. 특정 상태를 전제로 쓴 절차는 한 번 쓰고 못 쓴다 — 실제로 첫
판(세션 2개 전제)이 기기 초기화로 통째로 못 쓰게 됐다.

**기준선을 받아 적고, 이후 판정은 전부 그 값과의 차이로 한다.**

```bash
xcodegen generate
```

Xcode에서 실기기 타깃으로 Run (Debug). **`-MellowTrace`는 넣지 마라** —
`CaptureTrace`가 켜지면 콘솔이 200줄 넘게 밀린다.

### 0-1. 기준선 받아 적기

Run 직후 자동으로 찍힌다 (`ContentView`의 `.task` → `StoreProbeLog.inventory`).
**조작이 필요 없고, `@Query`가 이미 들고 있는 목록을 읽기만 한다.**

```
[probe] ═══ 재고 조사 — 앱 실행 직후
[probe] store     …/Library/Application Support/Mellow.store
[probe]           있음 …B
[probe] sessions  …/Documents/sessions
[probe]           있음  백업제외=true
[probe] 세션 N개 (스토어 기준)
[probe]  · <이름>  id=…
[probe]    디렉터리=있음  방향=<미정|portrait|landscape|없음(손상)|손상(…)>  메타 …컷 / 파일 …개  이어가기=<가능|불가>
[probe]      order=…  …s  ….mov  파일=…MB
…
[probe] tmp 남은 녹화본 N개  …
[probe] ═══
```

이 표를 채운다. 이후 모든 판정이 여기서 나온다.

| 칸 | 어디서 읽나 | 값 |
|---|---|---|
| 세션 수 `S` | `세션 N개 (스토어 기준)` | |
| `이어가기=불가` 세션 수 `X` | 각 세션 줄 | |
| 이어가기 대상 세션 | `이어가기=가능` 중 **가장 최근에 만들어진 것** | |
| └ id | `id=` | |
| └ 방향 | `방향=` | |
| └ 컷 수 | `메타 …컷` | |
| `.missing`/`손상` 세션 id | 있으면 전부 | |

세션이 하나도 없으면 `세션 0개 (스토어 기준)`만 찍히고 아래 목록이 비어 있다.
그것도 정상 기준선이다 — `S=0, X=0`.

### 0-2. 이번 실행에서 무엇을 찍을 수 있는지 가른다

| 조건 | 찍을 수 있는 항목 |
|---|---|
| 이어가기 대상이 **`방향=미정` · `0컷`** 이거나, 대상이 **없다**(`S=0` 또는 전부 불가) | **항목 1·2·4 전부** |
| 이어가기 대상이 `방향=portrait\|landscape` (클립이 이미 있다) | **항목 2만.** 항목 1·4는 못 찍는다 |
| `.missing`/`손상` 세션이 하나라도 있다 | **항목 3 추가** |

**항목 1은 "첫 클립"을 봐야 하므로 대상 세션이 비어 있어야 한다.** 이미 방향이
정해진 세션밖에 없으면 새 세션을 강제로 만들 방법이 없다 — 세션 닫기(2-12a)도
삭제(2-12)도 아직 없어서, 기기의 앱을 지우고 다시 설치하는 것 말고는 길이 없다.
**그 경우 `.missing` 픽스처가 함께 사라진다는 것을 알고 지워라** (실제로 그렇게
잃었다. Tasks.md 2-16 참고).

### 0-3. 전 구간 불변식

기준선에서 뽑아 두고, 매 단계 확인한다.

- `세션 시작` 탭마다 `[session] 이어가기 후보에서 제외 X개` — **X는 기준선의
  `이어가기=불가` 세션 수와 같다.** `X=0`이면 **이 줄이 아예 안 찍힌다.
  그것은 실패가 아니라 대상이 없는 것이다**
- 손대지 않은 세션의 `방향` · `메타 …컷 / 파일 …개` · `이어가기=`는 끝까지 불변

## 항목 1 — 첫 클립이 세션 방향을 정한다

**전제**: 0-2에서 "항목 1·2·4 전부"가 나왔을 것.

### 조작

1. 폰을 **정상 세로**로 든다 (홈 인디케이터가 아래)
2. **`세션 시작`** 탭 1회
3. 녹화 버튼 탭 1회 → **10초 자동 정지까지 기다린다**
   (조기 종료 금지 — 1초 미만이면 폐기되어 클립이 안 생긴다)
4. **`클립 저장`** 탭 1회

### 나와야 하는 콘솔

`세션 시작` — **기준선에 따라 두 갈래이고 둘 다 정상이다**:

```
(A) 이어갈 세션이 있었다 (기준선에 방향=미정·0컷 세션)
[probe] ▶ 이어가기  <이름>  id=<기준선 id와 같아야 한다>
[probe]   제목저장값=""  방향=미정  0컷

(B) 이어갈 세션이 없었다 (S=0 이거나 전부 불가)
[probe] + 새 세션  <오늘 날짜> 세션  id=<새 값>
[probe]   제목저장값=""  방향=미정  0컷
```

**어느 쪽이든 판정 대상은 둘째 줄의 `방향=미정  0컷`이다.** 여기가 `0컷`이
아니면 항목 1을 찍는 것이 아니다 — 0-2로 돌아가라.

녹화:

```
[rec] 회전각 고정 90.0
[rec] ▶ 시작 mellow-….mov
[rec] ⏱ 10초 한도 도달로 자동 종료 (파일 사용 가능=true)
[rec] 누른 시간 10.1…s / 파일 duration 9.9…s (차이 0.1…s)
[rec] ■ 저장 mellow-….mov — 누적 1개
── ClipSpec: mellow-….mov
   video.naturalSize    1920.0 x 1080.0
   video.transform      a:0.0 b:1.0 c:-1.0 d:0.0 tx:1080.0 ty:0.0
```

`클립 저장` — **판정 지점**:

```
[probe]   도출 방향=portrait  transform=a:0.0 b:1.0 c:-1.0 d:0.0 tx:1080.0 ty:0.0
[probe] ■ 클립 저장  order=0  9.9…s
[probe]   원본 …/tmp/mellow-….mov
[probe]        → 사라짐 ✓
[probe]   목적 …/Documents/sessions/…/clips/….mov
[probe]        → 있음 …MB
[probe]   세션 <이름> 의 order 목록 = 0
[probe]   방향=portrait
```

화면 노트: `저장 order=0 9.9…s · 방향 확정 portrait`

### 통과 기준

- `도출 방향=portrait`
- `transform=a:0.0 b:1.0 c:-1.0 d:0.0 tx:1080.0 ty:0.0` — CLAUDE.md 실측표의
  **세로(90)** 행
- `order=0`
- `[probe]   방향=portrait`
- 화면 노트가 **`방향 확정`**(`유지`가 아니다)

### 실패하면

| 증상 | 의심 |
|---|---|
| `방향=없음(손상)` | `alsoApply`가 `context.insert(clip)` **뒤에서** 불린다. 클립이 관계에 먼저 붙으면 `orientationState`가 `.missing`으로 보여 `.unset` 가드가 막는다 (`ClipStore.swift` 순서 확인) |
| `방향=미정` | 클립이 안 들어갔거나 다른 세션에 들어갔다. `order 목록`과 `id=` 대조 |
| 화면에 `방향 유지 …` | `decideOrientation`이 `false`를 냈다. 대상 세션이 이미 `.decided`거나 `.missing`이다 — 0-2 판단이 틀렸다 |
| `도출 방향=landscape` | 폰을 세로로 안 들었거나 `VideoTrackSpec.orientation` 문제. `[rec] 회전각 고정` 값부터 봐라 |
| `[clip] ✕ 저장 거부 … 비디오 트랙이 없다` | 녹화 파일이 깨졌다. 파일은 지워지지 않았으니 `tmp`에 남아 있다 |
| `→ ⚠ 아직 있음 (이동이 아니라 복사?)` | 2-8과 무관한 2-4 회귀 |

## 항목 4 — 거꾸로(180도) 촬영해도 `.portrait` 유지

항목 1 직후 같은 세션에 이어서 찍는다. **항목 2보다 먼저 해도 된다** —
재실행을 사이에 끼우지 않는 편이 로그를 읽기 쉽다.

### 조작

1. 폰을 **180도 돌려 거꾸로 세로**로 든다 (홈 인디케이터가 위).
   **눕히지 마라** — 가로는 계열이 달라 2-9 영역이다
2. 좌상단 오버레이에서 **`capture 각도  270.0`** 과
   **`기기 방향  portraitUpsideDown`**을 확인한다. 바뀔 때까지 1~2초 기다려라
3. 녹화 버튼 탭 1회 → 10초 자동 정지까지 기다린다
4. **`클립 저장`** 탭 1회

(앱을 재실행했다면 `activeSessionID`가 비어 있다. `클립 저장`이 비활성이면
**`세션 시작`을 먼저 탭해라.**)

### 나와야 하는 콘솔

```
[rec] 회전각 고정 270.0
── ClipSpec: mellow-….mov
   video.naturalSize    1920.0 x 1080.0
   video.transform      a:0.0 b:-1.0 c:1.0 d:0.0 tx:0.0 ty:1920.0
```

`클립 저장` — **판정 지점**:

```
[probe]   도출 방향=portrait  transform=a:0.0 b:-1.0 c:1.0 d:0.0 tx:0.0 ty:1920.0
[probe] ■ 클립 저장  order=1  9.9…s
[probe]   세션 <이름> 의 order 목록 = 0,1
[probe]   방향=portrait
```

화면 노트: `저장 order=1 9.9…s · 방향 유지 portrait`

### 통과 기준

- `[rec] 회전각 고정 270.0` — 거꾸로가 실제로 잡혔다
- `transform=a:0.0 b:-1.0 c:1.0 d:0.0 tx:0.0 ty:1920.0` — 실측표의
  **거꾸로(270)** 행
- **`도출 방향=portrait`** ← 이번 항목의 핵심
- `[probe]   방향=portrait` — 세션 방향이 바뀌지 않았다
- 화면 노트가 `방향 유지`(두 번째 클립이므로 `확정`이 아닌 것이 정상)

> **`도출 방향=landscape`인데 `방향=portrait`이면 통과가 아니라 실패다.**
> 세션 방향이 유지된 것은 가드가 막았기 때문이지 도출이 맞아서가 아니다.
> 그 상태로 2-9가 들어오면 계열 판정이 어긋난다.

### 실패하면

| 증상 | 의심 |
|---|---|
| `도출 방향=landscape` | `VideoTrackSpec.orientation`이 270 transform을 잘못 읽는다. 하네스 E군이 같은 케이스를 통과하므로, 실기기 파일의 `naturalSize`가 1920×1080이 아닐 가능성부터 본다 |
| `방향=landscape`로 바뀜 | `decideOrientation`이 두 번째 클립에서도 통과했다. `.decided` 가드가 안 걸린다 |
| `[rec] ✕ 지원하지 않는 회전각 270.0 — 기존 값 유지` | **이 회차는 무효다.** 파일에 이전 각도가 기록되어 거꾸로를 검증한 것이 아니게 된다. 다시 찍어라 |
| `회전각 고정 90.0`인데 폰은 거꾸로 | `RotationCoordinator`가 각도를 못 따라왔다. 2번 단계에서 오버레이를 확인하지 않고 바로 찍었을 가능성이 높다 |
| `video.transform`이 실측표 어느 행과도 안 맞음 | iPhone 12가 아니거나 카메라·프리셋이 바뀌었다. CLAUDE.md 실측표부터 다시 재야 한다 |
| `order 목록 = 0` | 저장이 실패했다. `[probe] ✕ 클립 저장 —` 확인 |

## 항목 2 — 앱 재실행 후 `세션 시작` → `.resumed`

### 조작

1. 앱을 **완전 종료** (앱 스위처에서 위로 밀기). Xcode Stop만으로는 부족하다
2. Xcode에서 다시 Run
3. **`세션 시작`** 탭 1회

### 나와야 하는 콘솔

실행 직후 자동:

```
[probe]  · <이름>  id=<항목 1과 같은 id>
[probe]    디렉터리=있음  방향=portrait  메타 2컷 / 파일 2개  이어가기=가능
[probe]      order=0  9.9…s  ….mov  파일=…MB
[probe]      order=1  9.9…s  ….mov  파일=…MB
```

`세션 시작`:

```
[probe] ▶ 이어가기  <이름>  id=<같은 id>
[probe]   제목저장값=""  방향=portrait  2컷
```

(항목 4를 아직 안 찍었으면 `1컷`이다.)

### 통과 기준

- **`[probe] ▶ 이어가기`** ← `.resumed`
- `id=`가 항목 1과 같은 값
- 재고의 `메타 …컷 / 파일 …개`가 **서로 같다**

**`[probe] + 새 세션`이면 실패다.** `.created`이고 F-01 AC가 깨진 것이다.

### 실패하면

| 증상 | 의심 |
|---|---|
| `+ 새 세션`, 재고는 `방향=없음(손상)` | 방향이 스토어에 안 들어갔다. 항목 1이 인메모리에서만 통과했을 수 있다 — `[probe] ✕ 클립 저장 —`을 거슬러 찾아라 |
| `+ 새 세션`, 재고는 `방향=portrait 이어가기=가능` | `resumableSession()`의 조회·필터 문제. `Session.inProgress()`와 `isResumable` |
| `제외` 줄의 수가 기준선 `X`보다 늘었다 | 방금 만든 세션이 후보에서 빠졌다 — `.missing`/`.corrupted`가 됐다는 뜻 |
| 재고에 `메타 2컷 / 파일 0개` | 파일 계층 문제(2-16 대상). 2-8과 별개로 보고 |

## 항목 3 — `.missing` 세션이 그대로 남아 있다

> **픽스처가 있을 때만 찍는다.** 0-1에서 `방향=없음(손상)` 또는 `방향=손상(…)`
> 세션을 적어 뒀으면 대상이 있는 것이다. 없으면 **이 항목은 건너뛴다** —
> 실패가 아니라 대상이 없는 것이다.
>
> 2-A 기기에 있던 픽스처는 소실됐다. 재확보 방법은 2-16에서 정한다
> (Tasks.md 2-16 참고).

### 조작

**없다.** 항목 1·2·4를 하면서 이미 찍힌 두 종류의 줄로 판정한다. 그 세션을
여는 조작이 절차에 들어가지 않는다.

### 나와야 하는 콘솔

앱 실행마다 (자동):

```
[probe]  · <이름>  id=<기준선 id>
[probe]    디렉터리=있음  방향=없음(손상)  메타 …컷 / 파일 …개  이어가기=불가
```

`세션 시작` 탭마다:

```
[session] 이어가기 후보에서 제외 X개 — 방향이 없거나 깨진 세션이다 (2-16 복구 대상)
```

화면 우상단 세션 목록에도 조작 없이 보인다:

```
<이름> · …컷 · 없음(손상) · 이어가기 불가
```

### 통과 기준

전 구간에서 기준선 값이 불변:

- `방향=없음(손상)` — 방향이 새로 붙지 않았다
- `메타 …컷 / 파일 …개` — 기준선과 같다
- `이어가기=불가`
- `제외 X개` — 매번 X (기준선의 불가 세션 수)

### 실패하면

| 증상 | 의심 |
|---|---|
| `방향=portrait`로 바뀜 | **가장 심각하다.** `decideOrientation`의 가드가 `.missing`을 통과시켰다. 계열이 다른 클립이 섞이면 정규화로 복구되지 않는다. 즉시 중단하고 `guard orientationState == .unset` 확인 |
| 컷 수가 늘었다 | 클립이 이 세션에 들어갔다. `activeSessionID`가 `startOrResume` 결과가 아닌 다른 것을 잡고 있다 |
| `제외 X-1개` | 이 세션이 후보에 들어갔다 — `isResumable`이 `.missing`을 통과시킨다 (2-7 회귀) |

## 실행 순서 요약

```
0. xcodegen generate → Run
   → 기준선 표를 받아 적는다 (세션 수 S / 불가 수 X / 대상 세션 상태)
   → 0-2 로 이번에 찍을 항목을 가른다
1. 세로로 들고 [세션 시작] → 녹화 10초 → [클립 저장]
   → 도출 방향=portrait · order=0 · 방향=portrait
4. 폰 180도 → capture 270 확인 → 녹화 10초 → [클립 저장]
   → 도출 방향=portrait · order=1 · 방향=portrait 유지
2. 앱 완전 종료 → Run → [세션 시작]
   → ▶ 이어가기 · 같은 id · 2컷
3. (조작 없음) 픽스처가 있으면 매 실행 재고에서 불변 확인
```

```
[probe]    디렉터리=있음  방향=…  메타 …컷
```
