# 2-8 실기기 검증 절차 (iPhone 12 · Xcode 콘솔)

세션 방향 확정(2-8)의 실기기 게이트다. 하네스(`Tools/StorageCheck.swift`)는
카메라 없이 도는 것만 본다 — 촬영·탭이 필요한 네 항목이 여기 있다.

**빌드 전제**: `be4b794`(도출 방향 로그) 이상이어야 한다. 그 이전 빌드로
돌리면 항목 4의 핵심 줄이 아예 찍히지 않는다.

## 콘솔로 판정 가능한가

| 항목 | 판정 | 근거 로그 |
|---|---|---|
| 1. 1컷 → `.decided` | 가능 | `[probe] 방향=portrait` (`savedClip` 마지막 줄) |
| 2. 재실행 후 `.resumed` | 가능 | `[probe] ▶ 이어가기` vs `[probe] + 새 세션` |
| 3. 01:29:07 세션 불변 | 가능 · **조작 불필요** | 앱 실행마다 자동으로 도는 `inventory`("앱 실행 직후") |
| 4. 거꾸로 촬영해도 `.portrait` | 가능 | `[probe]   도출 방향=` + `[probe]   방향=` 두 줄 |

3번은 세션을 여는 조작이 없다. `ContentView.swift`의 `.task`가 실행마다
`StoreProbeLog.inventory`를 찍고, 이 로그는 `@Query`가 이미 들고 있는 목록을
**읽기만** 한다.

**4번은 두 줄을 함께 봐야 한다.** `방향=`만 보면 도출이 틀려도 통과한다 —
두 번째 이후 클립은 `decideOrientation` 가드에 막혀 세션 방향을 어차피
바꾸지 않기 때문이다. 가드가 막아준 것과 도출이 맞은 것을 가르는 것이
`도출 방향=` 줄이다.

## 0. 준비

```bash
xcodegen generate
```

Xcode에서 실기기 타깃으로 Run (Debug). **`-MellowTrace`는 넣지 마라** —
`CaptureTrace`가 켜지면 콘솔이 200줄 넘게 밀린다.

앱이 뜨면 기준선이 자동으로 찍힌다.

```

[probe] store     /var/mobile/Containers/Data/Application/…/Library/Application Support/Mellow.store
[probe]           있음 77824B
[probe] sessions  /var/mobile/Containers/Data/Application/…/Documents/sessions
[probe]           있음  백업제외=true
[probe] 세션 2개 (스토어 기준)
[probe]  · 8월 17일 세션  id=…
[probe]    디렉터리=있음  방향=미정  메타 0컷 / 파일 0개  이어가기=가능
[probe]  · 01:29:07 세션  id=…
[probe]    디렉터리=있음  방향=없음(손상)  메타 2컷 / 파일 2개  이어가기=불가
[probe]      order=0  9.967s  ….mov  파일=19.2MB

[probe] ═══
```

**여기서 어긋나면 멈춰라**

- `세션 2개` — 3개 이상이면 이어가기 후보가 여럿일 수 있고,
  `[session] ⚠ 이어갈 수 있는 세션이 N개다`가 뜨면서 어느 세션에 클립이
  들어가는지 불확실해진다
- `8월 17일 세션 … 방향=미정 … 이어가기=가능`
- `01:29:07 세션 … 방향=없음(손상) … 이어가기=불가`, 메타 2컷 / 파일 2개

두 세션의 `id=`를 메모해라. 이후 전부 이 값으로 대조한다.

> **01:29:07 세션은 2-16 픽스처다. 열지도 말고 지우지도 마라.**
> 2-8 이전에 만들어진 `.missing` 세션이며, 정합성 복구가 실제로 그 상태를
> 만나야 한다.

## 항목 1 — 8월 17일 세션에 1컷 → `.decided`

### 조작

1. 폰을 **정상 세로**로 든다 (홈 인디케이터가 아래)
2. **`세션 시작`** 탭 1회
3. 녹화 버튼 탭 1회 → **10초 자동 정지까지 기다린다**
   (조기 종료 금지 — 1초 미만이면 폐기되어 클립이 안 생긴다)
4. **`클립 저장`** 탭 1회

### 나와야 하는 콘솔

`세션 시작`:

```
[session] 이어가기 후보에서 제외 1개 — 방향이 없거나 깨진 세션이다 (2-16 복구 대상)
[probe] ▶ 이어가기  8월 17일 세션  id=…
[probe]   제목저장값=""  방향=미정  0컷
[probe]   디렉터리 /var/…/Documents/sessions/…
[probe]   clips/ 있음=true  백업제외=true
```

녹화:

```
[rec] 회전각 고정 90.0
[rec] ▶ 시작 mellow-….mov
[rec] ⏱ 10초 한도 도달로 자동 종료 (파일 사용 가능=true)
[rec] 누른 시간 10.104s / 파일 duration 9.940s (차이 0.164s)
[rec] ■ 저장 mellow-….mov — 누적 1개
── ClipSpec: mellow-….mov
   video.naturalSize    1920.0 x 1080.0
   video.transform      a:0.0 b:1.0 c:-1.0 d:0.0 tx:1080.0 ty:0.0
```

`클립 저장` — **판정 지점**:

```
[probe]   도출 방향=portrait  transform=a:0.0 b:1.0 c:-1.0 d:0.0 tx:1080.0 ty:0.0
[probe] ■ 클립 저장  order=0  9.940s
[probe]   원본 /var/…/tmp/mellow-….mov
[probe]        → 사라짐 ✓
[probe]   목적 /var/…/Documents/sessions/…/clips/….mov
[probe]        → 있음 19.2MB
[probe]   세션 8월 17일 세션 의 order 목록 = 0
[probe]   방향=portrait
```

화면 노트: `저장 order=0 9.940s · 방향 확정 portrait`

### 통과 기준

- `[probe]   도출 방향=portrait`
- `transform=a:0.0 b:1.0 c:-1.0 d:0.0 tx:1080.0 ty:0.0` — CLAUDE.md
  실측표의 **세로(90)** 행과 일치
- `[probe]   방향=portrait`
- 화면 노트가 `방향 확정`(`유지`가 아니다)
- `▶ 이어가기`였다

### 실패하면

| 증상 | 의심 |
|---|---|
| `방향=없음(손상)` | `alsoApply`가 `context.insert(clip)` **뒤에서** 불린다. 클립이 관계에 먼저 붙으면 `orientationState`가 `.missing`으로 보여 `.unset` 가드가 막는다 (`ClipStore.swift` 순서 확인) |
| `방향=미정` | 클립이 안 들어갔거나 다른 세션에 들어갔다. `order 목록`과 `id=` 대조 |
| 화면에 `방향 유지 …` | `decideOrientation`이 `false`를 냈다. 세션이 이미 `.decided`거나 `.missing`이다 |
| `[clip] ✕ 저장 거부 … 비디오 트랙이 없다` | 녹화 파일이 깨졌다. 파일은 지워지지 않았으니 `tmp`에 남아 있다 |
| `→ ⚠ 아직 있음 (이동이 아니라 복사?)` | 2-8과 무관한 2-4 회귀 |

## 항목 2 — 앱 재실행 후 `세션 시작` → `.resumed`

### 조작

1. 앱을 **완전 종료** (앱 스위처에서 위로 밀기). Xcode Stop만으로는 부족하다
2. Xcode에서 다시 Run
3. **`세션 시작`** 탭 1회

### 나와야 하는 콘솔

실행 직후 자동:

```
[probe]  · 8월 17일 세션  id=…
[probe]    디렉터리=있음  방향=portrait  메타 1컷 / 파일 1개  이어가기=가능
[probe]      order=0  9.940s  ….mov  파일=19.2MB
```

`세션 시작`:

```
[session] 이어가기 후보에서 제외 1개 — 방향이 없거나 깨진 세션이다 (2-16 복구 대상)
[probe] ▶ 이어가기  8월 17일 세션  id=…
[probe]   제목저장값=""  방향=portrait  1컷
```

### 통과 기준

- **`[probe] ▶ 이어가기`** ← `.resumed`
- `id=`가 항목 1과 같은 값
- 재고에 `방향=portrait  메타 1컷 / 파일 1개`

**`[probe] + 새 세션`이면 실패다.** `.created`이고 F-01 AC가 깨진 것이다.

### 실패하면

| 증상 | 의심 |
|---|---|
| `+ 새 세션`, 재고는 `방향=없음(손상)` | 방향이 스토어에 안 들어갔다. 항목 1이 인메모리에서만 통과했을 수 있다 — `[probe] ✕ 클립 저장 —`을 거슬러 찾아라 |
| `+ 새 세션`, 재고는 `방향=portrait 이어가기=가능` | `resumableSession()`의 조회·필터 문제. `Session.inProgress()`와 `isResumable` |
| `제외 2개` | 8월 17일 세션까지 제외됐다 — `.missing`/`.corrupted`가 됐다는 뜻 |
| 재고에 `메타 1컷 / 파일 0개` | 파일 계층 문제(2-16 대상). 2-8과 별개로 보고 |

## 항목 3 — 01:29:07 세션이 그대로 남아 있다

> **⚠ 이 항목은 더 이상 재현되지 않는다.** 01:29:07 세션이 검증 뒤
> "전부 삭제"로 소실됐다. 기기에 `.missing` 세션이 없으므로 아래 기대
> 로그(`방향=없음(손상)`, `제외 1개`)가 나오지 않는다.
>
> 절차 자체는 남긴다 — 2-16이 픽스처를 다시 확보하면 그대로 쓴다.
> 픽스처 확보 방법은 2-16에서 정한다 (Tasks.md 2-16 참고).
>
> **픽스처 없이 이 절차를 다시 돌리면** 기준선의 `세션 2개`가 `1개`가
> 되고, `세션 시작` 때 `[session] 이어가기 후보에서 제외 …` 줄이 아예
> 찍히지 않는다. 그것은 실패가 아니라 대상이 없는 것이다.

### 조작

**없다.** 항목 1·2를 하면서 이미 찍힌 두 종류의 줄로 판정한다.

### 나와야 하는 콘솔

앱 실행마다 (자동):

```
[probe]  · 01:29:07 세션  id=…
[probe]    디렉터리=있음  방향=없음(손상)  메타 2컷 / 파일 2개  이어가기=불가
```

`세션 시작` 탭마다:

```
[session] 이어가기 후보에서 제외 1개 — 방향이 없거나 깨진 세션이다 (2-16 복구 대상)
```

화면 우상단 세션 목록에도 조작 없이 보인다:

```
01:29:07 세션 · 2컷 · 없음(손상) · 이어가기 불가
```

### 통과 기준

전 구간에서 네 값이 불변:

- `방향=없음(손상)` — 방향이 새로 붙지 않았다
- `메타 2컷 / 파일 2개`
- `이어가기=불가`
- `제외 1개` — 매번 1개

### 실패하면

| 증상 | 의심 |
|---|---|
| `방향=portrait`로 바뀜 | **가장 심각하다.** `decideOrientation`의 가드가 `.missing`을 통과시켰다. 계열이 다른 클립이 섞이면 정규화로 복구되지 않는다. 즉시 중단하고 `guard orientationState == .unset` 확인 |
| `메타 3컷` | 클립이 이 세션에 들어갔다. `activeSessionID`가 `startOrResume` 결과가 아닌 다른 것을 잡고 있다 |
| `제외 0개` | 이 세션이 후보에 들어갔다 — `isResumable`이 `.missing`을 통과시킨다 (2-7 회귀) |

## 항목 4 — 세로 → 거꾸로(180도) 촬영해도 `.portrait` 유지

항목 1·2를 끝낸 뒤(세로 1컷이 있는 상태) 이어서 한다.

### 조작

1. **`세션 시작`** 탭 1회
   (재실행했다면 `activeSessionID`가 비어 있다 — 다시 탭해야 `클립 저장`이 활성화된다)
2. 폰을 **180도 돌려 거꾸로 세로**로 든다 (홈 인디케이터가 위).
   **눕히지 마라** — 가로는 계열이 달라 2-9 영역이다
3. 좌상단 오버레이에서 **`capture 각도  270.0`** 과
   **`기기 방향  portraitUpsideDown`**을 확인한다. 값이 바뀔 때까지 1~2초 기다려라
4. 녹화 버튼 탭 1회 → 10초 자동 정지까지 기다린다
5. **`클립 저장`** 탭 1회

### 나와야 하는 콘솔

```
[rec] 회전각 고정 270.0
[rec] ▶ 시작 mellow-….mov
[rec] ⏱ 10초 한도 도달로 자동 종료 (파일 사용 가능=true)
── ClipSpec: mellow-….mov
   video.naturalSize    1920.0 x 1080.0
   video.transform      a:0.0 b:-1.0 c:1.0 d:0.0 tx:0.0 ty:1920.0
```

`클립 저장` — **판정 지점**:

```
[probe]   도출 방향=portrait  transform=a:0.0 b:-1.0 c:1.0 d:0.0 tx:0.0 ty:1920.0
[probe] ■ 클립 저장  order=1  9.938s
[probe]   세션 8월 17일 세션 의 order 목록 = 0,1
[probe]   방향=portrait
```

화면 노트: `저장 order=1 9.938s · 방향 유지 portrait`

### 통과 기준

- `[rec] 회전각 고정 270.0` — 거꾸로가 실제로 잡혔다
- `transform=a:0.0 b:-1.0 c:1.0 d:0.0 tx:0.0 ty:1920.0` — 실측표의
  **거꾸로(270)** 행과 일치
- **`[probe]   도출 방향=portrait`** ← 이번 항목의 핵심
- `[probe]   방향=portrait` — 세션 방향이 바뀌지 않았다
- 화면 노트가 `방향 유지`(두 번째 클립이므로 `확정`이 아닌 것이 정상)

> **`도출 방향=landscape`인데 `방향=portrait`이면 통과가 아니라 실패다.**
> 세션 방향이 유지된 것은 가드가 막았기 때문이지 도출이 맞아서가 아니다.
> 그 상태로 2-9가 들어오면 계열 판정이 어긋난다.

### 실패하면

| 증상 | 의심 |
|---|---|
| `도출 방향=landscape` | `VideoTrackSpec.orientation`이 270 transform을 잘못 읽는다. `naturalSize.applying(preferredTransform)`의 절대값 비교를 확인해라. 하네스 E군이 같은 케이스를 통과하므로, 실기기 파일의 `naturalSize`가 1920×1080이 아닐 가능성부터 본다 |
| `방향=landscape`로 바뀜 | `decideOrientation`이 두 번째 클립에서도 통과했다. `.decided` 가드가 안 걸린다 |
| `[rec] ✕ 지원하지 않는 회전각 270.0 — 기존 값 유지` | **이 회차는 무효다.** 파일에 이전 각도가 기록되어 거꾸로를 검증한 것이 아니게 된다. 다시 찍어라 |
| `회전각 고정 90.0`인데 폰은 거꾸로 | `RotationCoordinator`가 각도를 못 따라왔다. 3번 단계에서 오버레이를 확인하지 않고 바로 찍었을 가능성이 높다 |
| `video.transform`이 실측표 어느 행과도 안 맞음 | iPhone 12가 아니거나 카메라·프리셋이 바뀌었다. CLAUDE.md 실측표부터 다시 재야 한다 |
| `order 목록 = 0` | 저장이 실패했다. `[probe] ✕ 클립 저장 —` 확인 |

```

   → 도출 방향=portrait, 방향=portrait 유지
```

## 판정 결과를 남길 때 인용할 줄

콘솔에서 이 넷만 뽑으면 판정이 끝난다.

