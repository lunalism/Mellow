# 2-10 실기기 검증 절차 (iPhone 12 · Xcode 콘솔)

클립 0개가 되면 방향을 미정으로 초기화하는 것(2-10)의 실기기 게이트다.
초기화 자체와 실패 시 복원은 하네스(C군 · G군)가 값으로 검증하므로, 여기서
보는 것은 **실기기에서만 확인되는 것**이다.

그리고 이 절차에는 2-10 자체보다 **더 중요한 부수 효과가 있다.**

> **2-10이 들어와야 빈 세션을 임의로 만들 수 있다.** 클립을 전부 지우면
> 방향이 미정으로 돌아간 세션이 남는다. 그 전에는 빈 세션을 만들려면 앱을
> 지우는 수밖에 없었고, 그래서 **2-8 항목 1과 2-9 항목 4가 "미확인"으로
> 남아 있었다.** 이 절차가 그 둘을 닫는다.

**빌드 전제**: 2-10 구현이 들어간 커밋 이상. `[probe] ⌫ 클립 삭제` 블록에
`방향=` 줄이 있어야 항목 1이 성립한다. 그 이전 빌드에는 그 줄이 없다 —
초기화가 `ClipStore.delete` 안에서 일어나므로 **호출부에는 흔적이 없고**,
그 줄이 없으면 관측할 방법 자체가 없다.

## 콘솔로 판정 가능한가

| 항목 | 판정 | 근거 로그 |
|---|---|---|
| 1. 클립 0개 → 방향 미정 | **콘솔** | `[probe] 방향=미정  ← 0컷이므로 …` |
| 2. 빈 세션을 이어간다 | **콘솔** | `[probe] ▶ 이어가기` + `방향=미정` |
| 3. (2-8 항목 1) 세로 첫 컷 → portrait 도출 | **콘솔** | `[probe] 도출 방향=portrait` |
| 4. (2-9 항목 4) 미정 세션 + 가로 → 차단 안 됨 | 화면 | 버튼 그대로 |
| 5. 계열을 바꿔 다시 첫 컷 | **콘솔** | `[probe] 도출 방향=landscape` |

**항목 3·4·5가 이 절차의 본전이다.** 2-10은 항목 1 한 줄로 끝나고, 나머지는
2-10이 만들어준 빈 세션 덕분에 처음으로 찍을 수 있게 된 것들이다.

> **항목 5는 2-8·2-9 어느 쪽에도 없던 것이다.** 지금까지 가로 세션을 만들
> 방법이 없어(세로 세션에서는 가로 녹화가 차단된다) 가로 계열 도출과 가로
> 세션 차단이 실기기에서 확인된 적이 없다. 2-9 항목에 "가로 계열(0·180)은
> 이번에 못 봤다. 가로 세션이 생기면 그때 확인한다"고 적힌 것이 이것이다.

## 0. 준비 — 현재 상태를 먼저 기록한다

**기기 상태를 절차에 박지 않는다.** 2-8 절차서가 "세션 2개"를 전제로 썼다가
기기 초기화로 통째로 못 쓰게 됐다. 기준선을 받아 적고 그 값과의 차이로 본다.

```bash
xcodegen generate
```

Xcode에서 실기기 타깃으로 Run (Debug). **`-MellowTrace`는 넣지 마라** —
`CaptureTrace`가 켜지면 각도 변화가 매번 찍혀 콘솔이 밀린다.

> **⚠ Xcode Run은 콘솔을 지운다.** 이 절차에는 재실행이 없지만, 상태를
> 바꾸려고 앱을 다시 띄우면 그때까지의 로그가 날아간다. 2-8에서 항목 1의
> `도출 방향=` 줄을 그렇게 통째로 잃고 다시 찍었다. **재실행이 필요해질 것
> 같으면 `devicectl` + `tee`로 받아라.**
>
> ```
> xcrun devicectl device process launch --console --terminate-existing \
>   --device <UDID> com.lunalism.mellow | tee /tmp/2-10-device.log
> ```

### 0-1. 기준선 받아 적기

Run 직후 자동으로 찍힌다.

```
[probe] ═══ 재고 조사 — 앱 실행 직후
[probe] 세션 N개 (스토어 기준)
[probe]  · <이름>  id=…
[probe]    디렉터리=있음  방향=<미정|portrait|landscape|…>  메타 …컷 / 파일 …개  이어가기=<가능|불가>
[probe] ═══
```

| 칸 | 값 |
|---|---|
| 이어가기 대상 세션 (`이어가기=가능` 중 최신) | |
| └ 방향 | |
| └ 컷 수 | |

### 0-2. 시작 지점을 가른다

| 대상 세션의 상태 | 어디서 시작하나 |
|---|---|
| 방향 `portrait`, 컷 1개 이상 | **항목 1부터.** 그대로 쓴다 |
| 방향 `landscape`, 컷 1개 이상 | **항목 1부터.** 아래 표기를 세로↔가로 바꿔 읽는다 |
| 방향 `미정`, 0컷 | 항목 1을 건너뛰고 **항목 3부터.** 빈 세션이 이미 있다 |
| 이어갈 세션이 없음 | `세션 시작`을 탭해 만들고 **항목 3부터** |

**컷이 여러 개면 항목 1에서 전부 지우게 된다.** 지우기 싫은 세션이면 새 세션을
만들 수 없으므로(2-7이 이어가기를 강제한다) **먼저 그 세션을 다 지우거나,
기기에서 앱을 지우고 시작해라.** v0.1은 출시 전이라 잃을 데이터가 없다.

## 항목 1 — 마지막 컷을 지우면 방향이 미정으로 돌아간다

**전제**: 대상 세션에 클립이 1개 이상 있고 방향이 `portrait` 또는 `landscape`다.

### 조작

1. **`세션 시작`** 탭 — 이어가기 대상을 잡는다
2. **`마지막 컷 삭제`** 를 **컷이 0개가 될 때까지** 반복 탭

### 통과 기준

**마지막 한 컷을 지운 삭제**에서 이렇게 찍힌다.

```
[probe] ⌫ 클립 삭제  <uuid>.mov
[probe]   파일 지움  실제 확인=없음 ✓
[probe]   남은 0컷  · 비었음
[probe]   방향=미정  ← 0컷이므로 미정이어야 한다
[probe]   재정렬 후 order 목록 = (없음)  ✓ 저장 결과와 일치
```

**`방향=미정` 이 이 항목의 전부다.** 그 앞의 삭제들에서는 `방향=portrait`가
유지되어야 한다 — 0개가 되는 순간에만 초기화되는 것이 2-10이고, 그 전에
지워지면 남아 있는 클립과 다른 계열로 다음 촬영이 방향을 다시 정한다.

| 남은 컷 | 기대 `방향=` |
|---|---|
| 2컷 | `portrait` |
| 1컷 | `portrait` |
| **0컷** | **`미정`** |

### 실패하면

| 증상 | 의심 |
|---|---|
| 0컷인데 `방향=portrait` | 초기화가 안 돌았다. `remaining.isEmpty` 판정이 `session.clips` 를 보고 있는지 확인해라 — **`context.delete(clip)` 은 관계를 그 자리에서 비우지 않는다**(실측). 미리 계산한 `remaining` 을 써야 한다 |
| 0컷인데 `방향=없음(손상)` | **`.missing` 을 직접 만들었다.** 방향 초기화가 삭제보다 **앞**에 있다. Tasks.md 2-10 "함정 (가)" |
| 1컷 남았는데 `방향=미정` | 초기화 조건이 `remainingCount == 1` 이거나 off-by-one 이다 |
| `⚠ 개수 불일치` / `0..< 연속이 아님` | 2-5 재정렬 문제다. 2-10과 별개이며 그쪽을 먼저 봐라 |

## 항목 2 — 빈 세션이 이어가기 후보로 남는다

**전제**: 항목 1을 마쳤다(0컷·미정 세션이 있다).

### 조작

1. **`재고 조사`** 탭 (또는 앱을 다시 띄운다)

### 통과 기준

```
[probe]  · <이름>  id=<항목 1과 같은 id>
[probe]    디렉터리=있음  방향=미정  메타 0컷 / 파일 0개  이어가기=가능
```

- **`id`가 항목 1의 세션과 같다** — 세션이 지워지지 않았다
- **`이어가기=가능`** — `.unset`이라 `isResumable`이 참이다

세션은 남고 방향만 되돌아간다. PRD 3장 "첫 클립을 undo해서 클립이 0개가 되면
방향은 미정 상태로 되돌아간다. **잘못된 방향으로 첫 컷을 찍었을 때의
탈출구다**" 가 이것이다.

### 실패하면

| 증상 | 의심 |
|---|---|
| `이어가기=불가` | 방향이 `.missing`/`.corrupted`로 남았다. 항목 1의 `방향=` 줄을 다시 봐라 |
| 세션이 목록에서 사라졌다 | 2-10이 세션까지 지웠다. **지우면 안 된다** — 2-12가 할 일이다 |
| `파일 0개`가 아니다 | 고아 파일이다. 2-16 대상이며 2-10 실패는 아니다 |

## 항목 3 — (2-8 항목 1 닫기) 세로 첫 컷이 portrait을 도출한다

> **2-8에서 "조건부 통과"로 남은 항목이다.** `order=0`의 `도출 방향=` 줄이
> 콘솔 유실로 없었고, **세로(90) → portrait 도출이 실기기에서 미확인**이었다.
> 빈 세션이 필요한데 만들 방법이 없어 미뤄졌다.

**전제**: 0컷·미정 세션(항목 1의 결과)

### 조작

1. 폰을 **세로로** 들고
2. **`세션 시작`** → 녹화 → 자동 정지까지 두거나 다시 탭해 종료
3. **`클립 저장`** 탭

### 통과 기준

```
[probe]   도출 방향=portrait  transform=a:0.0 b:1.0 c:-1.0 d:0.0 tx:1080.0 ty:0.0
[probe] ■ 클립 저장  order=0  9.xxx s
[probe]   세션 … 의 order 목록 = 0
[probe]   방향=portrait
```

**두 줄을 함께 봐야 한다.**

- `도출 방향=portrait` — 파일에서 도출한 값이 맞다
- `방향=portrait` — 그 값이 세션에 실제로 붙었다

`transform`이 CLAUDE.md 실측표의 **세로(90) 행**과 일치해야 한다
(`tx:1080 ty:0`). 거꾸로(270) 행은 `tx:0 ty:1920`이라 명확히 다르다.

**`order=0`이어야 한다.** 항목 1에서 클립이 0개가 됐으므로 `nextOrder`가
최대값+1 = 0을 낸다. `order=4` 같은 값이 나오면 클립이 덜 지워진 것이다.

### 실패하면

| 증상 | 의심 |
|---|---|
| `도출 방향=landscape` | 도출이 틀렸다. `transform` 값을 실측표와 대조해 어느 행인지 먼저 확인해라 |
| `방향=미정` | `decideOrientation`이 `false`를 냈다. 세션이 `.unset`이 아니었다는 뜻이며 항목 1·2를 다시 봐라 |
| `저장 거부: 방향 판정 불가` | 정사각 트랙이다. 프리셋을 확인해라 |

## 항목 4 — (2-9 항목 4 닫기) 미정 세션에서는 가로로 들어도 차단되지 않는다

> **2-9에서 "미정 세션이 기기에 없었다"로 미확인이던 항목이다.**

**전제**: 0컷·미정 세션. **항목 3을 찍었으면 다시 비워야 한다** — 항목 1을
한 번 더 돌려라(컷 1개라 삭제 한 번이면 된다).

### 조작

1. **`세션 시작`** 탭
2. 폰을 **가로로** 눕힌다

### 통과 기준

- 녹화 버튼이 **그대로다** (흐려지지 않는다)
- **안내가 뜨지 않는다**

첫 클립이 세션 방향을 정하므로(2-8) 아직 방향이 없는 세션에서 막으면 세로로도
가로로도 시작할 수 없다.

**콘솔에는 흔적이 없다.** 차단은 뷰의 `.disabled`라 로그를 남기지 않는다 —
판정이 순수 함수라 부작용이 없어서이고 그것이 의도다. **화면 관찰로 판정하고,
판정 근거가 화면이라는 것을 결과에 적어라** (2-8에서 화면 관찰이 가드 검증으로
잘못 읽힌 사례가 있다).

### 실패하면

| 증상 | 의심 |
|---|---|
| 차단된다 | 뷰가 다른 세션을 보고 있다. 하네스 F군 "미정 세션 + 기기 가로 → 통과"는 통과하는데 실기기에서 막히면 그쪽이다 |

## 항목 5 — 가로 세션을 처음으로 만든다

> **지금까지 실기기에서 한 번도 못 본 경로다.** 세로 세션에서는 가로 녹화가
> 차단되므로 가로 세션을 만들려면 미정 세션에서 가로로 첫 컷을 찍어야 하는데,
> 미정 세션을 만들 방법이 없었다.

**전제**: 항목 4의 상태 그대로 (0컷·미정 세션 + 폰이 가로)

### 조작

1. 가로로 든 채 녹화 → 종료 → **`클립 저장`**
2. 저장 후 폰을 **세로로** 세운다

### 통과 기준

저장 시:

```
[probe]   도출 방향=landscape  transform=a:1.0 b:0.0 c:0.0 d:1.0 tx:0.0 ty:0.0
[probe]   방향=landscape
```

`transform`이 실측표의 **가로L(0) 행** 또는 **가로R(180) 행**
(`a:-1 d:-1 tx:1920 ty:1080`)과 일치해야 한다. 어느 쪽이든 도출은
`landscape`다 — 계열 내 180도가 한 값으로 접히는 것이 `Orientation`이 2값인
이유다.

세로로 세운 뒤:

- 녹화 버튼이 **흐려진다**
- **"가로로 들고 촬영하세요"** 안내가 뜬다

**이것이 2-9의 가로 세션 차단을 실기기에서 처음 확인하는 순간이다.**

### 실패하면

| 증상 | 의심 |
|---|---|
| `도출 방향=portrait` | 도출이 틀렸다. `transform`을 실측표와 대조해라 |
| 세로로 세워도 차단 안 됨 | `RecordingGate`가 세션 방향을 못 읽고 있다. `방향=landscape`가 찍혔는지 먼저 확인 |
| 안내 문구가 "세로로" | 문구가 세션 방향이 아니라 기기 방향을 말하고 있다 |

## 실행 순서 요약

```
0. xcodegen generate → Run → 기준선 표를 받아 적고 0-2로 시작 지점을 가른다
1. [세션 시작] → [마지막 컷 삭제] × N       → 0컷에서 방향=미정
2. [재고 조사]                              → 같은 id · 방향=미정 · 이어가기=가능
3. 세로로 들고 녹화 → [클립 저장]           → 도출 방향=portrait  ← 2-8 항목 1 닫힘
   └ [마지막 컷 삭제] 로 다시 비운다
4. 가로로 눕힌다                            → 차단 안 됨          ← 2-9 항목 4 닫힘
5. 가로로 녹화 → [클립 저장] → 세로로 세움  → landscape 도출 + 세로에서 차단
```

**3 다음에 다시 비우는 단계를 빠뜨리지 마라.** 항목 3이 세션을 `portrait`으로
만들어 버리므로, 그대로 항목 4로 가면 가로에서 **차단되는 것이 정상**이 되어
판정이 뒤집힌다.

## 판정 결과를 남길 때 인용할 줄

```
[probe]   방향=<미정|portrait|landscape|없음(손상)>
[probe]   도출 방향=<portrait|landscape>  transform=…
[probe]    디렉터리=…  방향=…  메타 …컷 / 파일 …개  이어가기=…
```

항목 4는 콘솔에 흔적이 없으므로 **화면 관찰을 그대로 적고, 근거가 화면임을
밝혀라.**

결과는 `Tasks.md`에 기록한다 — 2-10 항목에, 그리고 **닫힌 항목은 2-8·2-9
항목에도** 적는다. 이 문서는 절차만 들고 있다.
