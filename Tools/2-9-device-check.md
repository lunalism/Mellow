# 2-9 실기기 검증 절차 (iPhone 12 · Xcode 콘솔)

방향 불일치 시 녹화 차단(2-9)의 실기기 게이트다. 판정 로직 자체는 하네스
F군이 값으로 검증하므로, 여기서 보는 것은 **실기기에서만 확인되는 셋**이다.

- 기기를 실제로 돌렸을 때 판정이 따라오는가 (하네스는 값을 넣어줄 뿐이다)
- 버튼·안내가 눈에 보이게 바뀌는가
- **판정 소스와 파일 transform 소스가 어긋나지 않는가** — 이것이 이 게이트의
  핵심이고, 어긋나면 버튼은 통과시켰는데 파일은 다른 계열로 찍힌다

**빌드 전제**: 2-9 구현이 들어간 커밋 이상. `[rec] 판정 …` 로그가 있어야
6번 항목이 성립한다.

## 콘솔로 판정 가능한가

| 항목 | 판정 | 근거 |
|---|---|---|
| 1. 세로 세션 + 가로 → 차단 | 화면 | 버튼 흐려짐 + 안내 |
| 2. 다시 세로 → 해제 | 화면 | 버튼 복귀 + 안내 사라짐 |
| 3. 거꾸로(180도) → 차단 안 됨 | 화면 | 버튼 그대로 |
| 4. `.unset` 세션 + 가로 → 차단 안 됨 | 화면 | 버튼 그대로 |
| 5. 경계 왕복 → 깜빡임 | **눈으로만** | (C) 판단의 근거 |
| 6. 두 소스 일치 | **콘솔** | `[rec] 판정 …` |

**1~5는 콘솔에 흔적이 없다.** 차단은 뷰의 `.disabled`라 로그를 남기지
않는다 — 판정이 순수 함수라 부작용이 없기 때문이고, 그것이 의도다.
**녹화를 시작해야 로그가 남으므로 6번만 콘솔로 본다.**

---

## 0. 준비 — 현재 상태를 먼저 기록한다

**기기 상태를 절차에 박지 않는다.** 2-8 절차서가 "세션 2개" 를 전제로 썼다가
기기 초기화로 통째로 못 쓰게 됐다. 기준선을 받아 적고 그 값과의 차이로 본다.

```bash
xcodegen generate
```

Xcode에서 실기기 타깃으로 Run (Debug). **`-MellowTrace`는 넣지 마라** —
`CaptureTrace`가 켜지면 각도 변화가 매번 찍혀 콘솔이 밀린다. 이 절차는
각도 전이가 아니라 **녹화 시작 시점의 값**을 본다.

> **⚠ Xcode Run은 콘솔을 지운다.** 이 절차에는 재실행이 없지만, 세션 상태를
> 바꾸려고 앱을 다시 띄우면 그때까지의 로그가 날아간다. **6번 로그를 확보한
> 뒤에는 재실행하지 마라.** 항목 순서를 그렇게 짰다 — 촬영이 필요한 6번이
> 마지막이다.

### 0-1. 기준선 받아 적기

Run 직후 자동으로 찍힌다.

```
[probe] ═══ 재고 조사 — 앱 실행 직후
[probe] 세션 N개 (스토어 기준)
[probe]  · <이름>  id=…
[probe]    디렉터리=있음  방향=<미정|portrait|landscape|…>  메타 …컷 / 파일 …개  이어가기=<가능|불가>
[probe] ═══
```

| 칸 | 값 |
|---|---|
| 이어가기 대상 세션 (`이어가기=가능` 중 최신) | |
| └ 방향 | |
| └ 컷 수 | |

### 0-2. 이번 실행에서 무엇을 찍을 수 있는지 가른다

| 대상 세션의 방향 | 찍을 수 있는 항목 |
|---|---|
| `portrait` | **1·2·3·5·6** (세로 세션 기준) |
| `landscape` | 1·2·5·6을 **방향만 바꿔** 읽는다 (가로 세션에서 세로로 들면 차단) |
| `미정` · 세션 없음 | **4만.** 1·2·3·6은 방향이 정해진 세션이 필요하다 |

**대상이 `미정`이면 4번을 먼저 찍고, 세로 1컷을 저장해 `portrait`으로 만든
뒤 나머지를 이어서 찍는다.** 그 저장이 2-8 항목 1의 재확인도 겸한다.

### 0-3. 화면에서 볼 것

- 좌상단 오버레이의 **`기기 방향`** 행 — `portrait` / `landscapeLeft` /
  `landscapeRight` / `portraitUpsideDown` / `faceUp` / `faceDown`
- 하단 **녹화 버튼** — 차단되면 **흐려지고(35%) 살짝 작아진다**
- 버튼 바로 위 **안내 캡슐** — 차단될 때만 나타난다

**세션 방향은 촬영 화면에 표시되지 않는다.** 상시 표시를 두지 않는 것이
결정이므로(3-6) 세션 방향은 우상단 세션 목록에서 확인한다.

## 항목 1 — 세로 세션에서 가로로 들면 차단된다

**전제**: 대상 세션이 `portrait`.

### 조작

1. **`세션 시작`** 탭 1회 (활성 세션을 잡는다)
2. 폰을 정상 세로로 든 상태에서 녹화 버튼이 **정상(불투명)** 인지 확인
3. 폰을 **가로로 눕힌다** (어느 쪽이든 된다)
4. 좌상단 `기기 방향`이 `landscapeLeft` 또는 `landscapeRight`로 바뀔 때까지
   기다린다 (1~2초)

### 통과 기준

- 녹화 버튼이 **흐려지고 작아진다**
- 버튼 위에 **`세로로 들고 촬영하세요`** 캡슐이 뜬다
- 버튼을 눌러도 **아무 일도 일어나지 않는다** (`[rec] ▶ 시작` 이 안 찍힌다)

### 실패하면

| 증상 | 의심 |
|---|---|
| 버튼이 그대로다 | 활성 세션이 없다(`세션 시작` 안 누름) → `recordingGate`가 `.allowed`. 또는 세션 방향이 `미정` |
| 버튼은 흐린데 눌린다 | `.disabled` 가 안 걸렸다. `opacity`만 적용된 것 |
| 안내가 안 뜬다 | `orientationNotice`가 `isRecordingBlocked`를 안 보고 있다 |
| 안내 문구가 `가로로…` | 세션 방향이 `landscape`다. 0-1을 다시 봐라 |
| `기기 방향`이 안 바뀐다 | `beginGeneratingDeviceOrientationNotifications` 문제. 폰을 더 확실히 눕혀라 |

---

## 항목 2 — 다시 세로로 들면 해제된다

항목 1 직후 이어서.

### 조작

폰을 **다시 정상 세로로** 세운다.

### 통과 기준

- 녹화 버튼이 **원래대로 돌아온다** (불투명, 원래 크기)
- **안내 캡슐이 사라진다**
- 버튼이 눌린다 (여기서 실제로 찍을 필요는 없다)

### 실패하면

| 증상 | 의심 |
|---|---|
| 안내가 남아 있다 | 상태를 들고 있다는 뜻이다 — **마지막 계열을 기억하지 않는 것이 결정**이므로(2-9 (B)) 어딘가에 캐시가 생긴 것 |
| 버튼이 안 돌아온다 | 위와 같음 |

---

## 항목 3 — 거꾸로(180도)는 차단되지 않는다

**계열 내 180도를 막지 않는 것이 결정이다.** 막으면 로우앵글 촬영이 막힌다.

### 조작

1. 폰을 **180도 돌려 거꾸로 세로**로 든다 (홈 인디케이터가 위)
2. 좌상단 `기기 방향`이 **`portraitUpsideDown`** 이 될 때까지 기다린다

### 통과 기준

- 녹화 버튼이 **그대로다** (흐려지지 않는다)
- **안내가 뜨지 않는다**
- 버튼이 눌린다

`portraitUpsideDown`은 `UIDeviceOrientationIsPortrait`가 참이라 계열이
`.portrait`으로 접힌다 — 세션 방향과 같으므로 통과다.

### 실패하면

| 증상 | 의심 |
|---|---|
| 차단된다 | 계열 매핑이 깨졌다. `UIDeviceOrientation.family`가 `isPortrait`이 아니라 케이스별 매칭을 하고 있는지 봐라 — **각도·케이스 테이블을 만들지 않는 것이 이 경로를 고른 이유다** |

---

## 항목 4 — `.unset` 세션에서는 차단되지 않는다

**전제**: 대상 세션이 `미정`(0컷)이거나, 활성 세션이 없다.

### 조작

1. **`세션 시작`** 탭 (0컷·미정 세션을 잡는다)
2. 폰을 **가로로** 눕힌다

### 통과 기준

- 녹화 버튼이 **그대로다**
- **안내가 뜨지 않는다**

첫 클립이 세션 방향을 정하므로(2-8) 아직 방향이 없는 세션에서 막으면
세로로도 가로로도 시작할 수 없다.

### 실패하면

| 증상 | 의심 |
|---|---|
| 차단된다 | `RecordingGate`가 `.unset`을 `.decided`처럼 다룬다. 하네스 F군 "미정 세션 + 기기 가로 → 통과"가 통과하는데 실기기에서 막히면 **뷰가 다른 세션을 보고 있는 것**이다 |

## 항목 5 — 경계 각도 왕복 (깜빡임 관찰)

> **(C) 히스테리시스 판단의 근거가 되는 항목이다.** 지금은 임계값 처리를
> 만들지 않았다 — 필요하다는 실측도 불필요하다는 실측도 없어서, 추측으로
> 임계값을 정하지 않기로 했다. **이 관찰이 그 공백을 메운다.**

### 조작

폰을 세로에서 가로로 **아주 천천히** 기울인다. 45도 부근에서 **멈추고,
좌우로 조금씩 흔든다.** 반대 방향으로도 같은 방식으로 왕복한다.

### 볼 것

- 녹화 버튼의 투명도가 **깜빡이는가** (흐려졌다 돌아왔다를 반복)
- 안내 캡슐이 **떴다 사라졌다** 하는가
- 좌상단 `기기 방향` 값이 경계에서 **튀는가**

### 판정

| 관찰 | 결론 |
|---|---|
| 깜빡임이 **없다** | (C) 유지. 히스테리시스를 만들지 않는다. **관찰 결과를 Tasks.md 2-9에 기록해 근거를 남긴다** |
| 깜빡임이 **있다** | (C) 재검토. 그때 임계값을 정한다 — **이 관찰이 임계값의 근거가 된다.** 몇 도 범위에서 몇 번 튀는지 함께 적어라 |

`UIDevice`의 방향 통지는 자체 임계값을 갖고 있어 각도 그대로 따라오지
않는다. **깜빡임이 없을 가능성이 실제로 있고, 그 경우 우리가 임계값을
겹쳐 넣을 이유가 없다.**

## 항목 6 — 두 소스가 일치하는가 (콘솔)

**이 게이트의 핵심이다.** 판정은 UIKit이 하고 파일 transform은
`RotationCoordinator`가 정한다. 둘이 어긋나면 **버튼은 통과시켰는데 파일은
다른 계열로 찍히고**, 그 클립을 2-8이 세션 방향과 다른 계열로 판정한다.

### 조작

각 방향에서 **녹화를 실제로 시작한다.** (10초를 다 채울 필요는 없다 —
로그는 시작 시점에 찍힌다. 다만 1초 미만은 폐기되므로 2초쯤 두고 다시 탭)

1. 정상 세로 → 녹화 시작 → 정지
2. 거꾸로 세로 → 녹화 시작 → 정지
3. (가로 세션이면) 가로L / 가로R에서 각각

### 나와야 하는 콘솔

```
[rec] 판정 portrait  UIDevice=portrait  capture각도=90.0
[rec] 회전각 고정 90.0
[rec] ▶ 시작 mellow-….mov
```

### 통과 기준 — CLAUDE.md 실측표와 대조

| `UIDevice` | 계열 | `capture각도` |
|---|---|---|
| `portrait` | portrait | **90** |
| `portraitUpsideDown` | portrait | **270** |
| `landscapeLeft` | landscape | **0** |
| `landscapeRight` | landscape | **180** |

- `판정` 값이 `UIDevice` 값의 계열과 맞는가 (portrait 둘, landscape 둘)
- `capture각도`가 위 표와 맞는가
- **`판정`과 `capture각도`가 같은 계열을 가리키는가** ← 이것이 핵심이다.
  90·270이면 세로, 0·180이면 가로여야 한다

### 실패하면

| 증상 | 의심 |
|---|---|
| `판정 portrait` 인데 `capture각도=0` | **두 소스가 어긋났다.** 이 조합이 나오면 버튼 판정과 파일 내용이 갈린다는 뜻이고, 2-9의 판정 소스 결정(A)을 다시 봐야 한다. **각도와 UIDevice 값을 모두 적어 보고해라** |
| `판정 없음` | `faceUp`/`faceDown` 상태에서 찍었다. 폰을 세우고 다시 |
| `capture각도=—` | `rotationCoordinator`가 아직 없다. 프리뷰 레이어가 붙기 전이다 |

**어긋남이 나오면 그 자리에서 멈춰라.** 파일이 세션 방향과 다른 계열로
들어가면 계열 간 혼재가 되고, 정규화로도 복구되지 않는다.

## 실행 순서 요약

```
0. xcodegen generate → Run → 기준선 표를 받아 적고 0-2로 항목을 가른다
1. [세션 시작] → 가로로 눕힌다        → 버튼 흐려짐 + "세로로 들고 촬영하세요"
2. 다시 세로                          → 버튼 복귀 + 안내 사라짐
3. 거꾸로(180도)                      → 차단 안 됨
4. (미정 세션에서) 가로               → 차단 안 됨
5. 경계 45도 부근 왕복                → 깜빡임 관찰  ← (C) 판단 근거
6. 각 방향에서 녹화 시작              → [rec] 판정 … 로그 대조
   ── 6번 로그를 확보한 뒤에는 재실행하지 마라. 콘솔이 지워진다 ──
```

## 판정 결과를 남길 때 인용할 줄

```
[rec] 판정 <계열>  UIDevice=<orientation>  capture각도=<angle>
```

1~5는 콘솔에 흔적이 없으므로 **화면 관찰을 그대로 적는다.** 2-8에서
"화면 관찰이 가드를 검증한 것으로 잘못 읽힌" 사례가 있었으므로,
**무엇을 보고 판정했는지(화면인지 콘솔인지)를 함께 적어라.**

결과는 `Tasks.md`의 2-9 항목에 기록한다. 이 문서는 절차만 들고 있다.
